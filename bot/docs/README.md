# Homes in Georgia AI — ИИ-подборщик квартир (прототип → полная версия)

Прототип для агентства **Rent in Tbilisi** (канал [@rent_tbilisi_ge](https://t.me/rent_tbilisi_ge), агент Давид).
Собран 15–16.10.2026.

## Этап 2: общая PostgreSQL и путь клиента (02.11.2026)

Бот работает на общей базе платформы (PostgreSQL, схема — `backend/alembic`, контракт — `docs/ARCHITECTURE.md`).
Что поменялось относительно описания ниже (оно про прототип на SQLite):

- `db.py` — слой над psycopg 3 с API как у sqlite3 (`?`/`:name`, строки по ключу и индексу, `INSERT OR IGNORE`);
  `DATABASE_URL` из окружения или `.env` в корне репозитория. `db.py init` только досеивает настройки и источники.
  Таблицы `agents` нет: сотрудники — `users` (role operator/agent/admin/superadmin/recruit, `tg_id`, `is_active`).
  `agents.json` больше не импортируется: сотрудников заводят в CRM или командой `/agent <код>`.
- `journey.py` — путь клиента из `docs/user-journey.txt`: анкета на /start (A1a-A2a, `clients.profile`, один раз),
  ❤️ → заявка в CRM (`app.services.leads.create_from_like`, A3: та же карточка меняется), группа операторов
  (B1/B3: «✋ Взять заявку» → «👤 Назначить агента» → список агентов), агент вводит время кнопками или текстом (C7),
  клиент выбирает время (A4), опаздываю/перенести, итог просмотра (A5/C9a), причина отказа, T14 (A6).
- Исходящие сообщения CRM/воркера — `backend/app/telegram/notify.py` (Bot API через `client.py`).
- Клиентский каталог всегда ограничен опубликованными объявлениями канала агентства и объектами,
  опубликованными через воронку 1. Сырые объявления парсеров доступны только сотрудникам.
- Телефоны, которые агенты отметили «ответил агент» (`owners.is_agent`), при `db.py sync` помечают объявление
  «похоже на агента» (pending_review + причина).
- `admin.py` устарел (заменён React CRM) и не перенесён на PostgreSQL. Страницы `/map` (`webapp/index.html`, карта для
  клиентов) и `/journey` должен отдавать backend: бот ссылается на `PUBLIC_URL/map`.

Запуск (из корня репозитория, общий `.venv`; схема: `cd backend && ../.venv/bin/alembic upgrade head`):

```
.venv/bin/python -m bot.run --check     # проверка базы: досеять настройки/источники, статистика
.venv/bin/python -m bot.run             # бот (long polling): BOT_TOKEN, PUBLIC_URL, OPERATORS_CHAT_ID, AGENT_CODE
bot/refresh.sh                          # одно обновление базы объявлений (fetchers → ingest → db.py sync → embed)
bot/refresh_loop.sh                     # процесс refresh: сразу и каждые REFRESH_HOURS
cd bot && ../.venv/bin/python -m unittest discover -s test   # тесты (TEST_DATABASE_URL, схема bot_test)
```

Тесты идут в отдельной схеме `bot_test` базы `TEST_DATABASE_URL` (схему создаёт `alembic upgrade head`, при смене
миграций пересоздаётся). `test/test_journey_e2e.py` прогоняет весь путь клиента через настоящий бот и сервисы backend
против фейкового Bot API (`test/e2e/fake_tg.py`, `TG_API_BASE`); LLM и геокодинг подменены.

## Зачем

Станислав предложил агентству ИИ-поиск: клиент пишет запрос (и по желанию кидает картинки), бот подбирает квартиры.
Давид ответил голосовым и добавил главное условие (см. [client-conversation.md](client-conversation.md)):

- бот ищет не только квартиры агентства, но и **реальных собственников** на myhome.ge, ss.ge (и Facebook-группах);
- клиент видит **только фото и описание**: без ссылки, источника и телефона;
- если клиент говорит «нравится», **агент получает ссылку**, сам звонит собственнику и договаривается;
- нужно быть уверенным, что это **реально собственник**: телефоны и адреса не повторяются и т.п.

## Как работает

```
refresh.sh (по расписанию):
  db.py export-sources  →  sources.json (источники хранятся в базе)
  fetch_ss.py / fetch_myhome.py / fetch_channel.py / fetch_facebook.py  →  raw/*.json + raw/img/
  ingest.py  →  нормализация → фото → отпечатки фото → отсев агентов → дедуп → геокодинг → индексация Codex
             →  listings.json + raw/dropped_agents.json
  db.py sync →  data/app.db: новые добавлены, пропавшие = gone, агенты = rejected, сомнительные = pending_review
data/app.db  →  SQLite, единственный источник правды (схема: docs/schema.md)
core.py    →  логика без Telegram: клиенты, подбор, реакции, лиды и их статусы, модерация, тексты ru/en
bot.py     →  тонкий Telegram-адаптер над core.py (@tbilisi_rent_ai_demo_bot): клиенты, лиды и проверка для агентов
webapp/    →  страница-карта (Telegram Mini App) на https://tbilisi-rent-map.vercel.app
```

### Архитектура полной версии (этап 1 ТЗ)

- **База** (`db.py`, `data/app.db`, в git не попадает): объявления со статусами `published / pending_review / rejected / gone`,
  клиенты, реакции, лиды со статусами и историей, агенты, источники, настройки. Подробно — [schema.md](schema.md).
- **Ядро** (`core.py`) не знает про Telegram: `client()`, `add_input()`, `search()`, `card()`, `react()`,
  `set_lead_status()`, `pending()`, `moderate()`, `staff_chats()`. Состояние клиента (запрос, показанные, лайки)
  хранится в базе, поэтому переживает перезапуск бота. Сайт или WhatsApp — это ещё один адаптер, который зовёт те же
  функции с `channel="web"` / `"whatsapp"`.
- **Клиентам показываются только `published`.** Карточка проходит через `core.public()`: вырезаются ссылки, @ники,
  телефоны, названия сайтов и агентств-конкурентов.
- **Языки**: клиенту отвечаем на русском или английском — по тексту его сообщений (кириллица/латиница), иначе по языку
  Telegram. Подбор Codex пишет «как понял» и «почему подходит» на языке клиента; описание квартиры переводится на
  английский при первом показе и сохраняется в базе (`description_en`). Бренд — Homes in Georgia (с 19.10.2026, раньше Rent in Tbilisi).
- **Проверка человеком**: объявления `pending_review` бот раз в 10 минут (по `review_batch` штук) шлёт агентам с
  кнопками «✅ Опубликовать / ❌ Отклонить». Решение сохраняется (`decision`) и не перетирается следующей синхронизацией.
- **Лиды**: «❤️ Нравится» → лид в базе + карточка агентам (источник, все ссылки) с кнопками статуса «🛠 В работе /
  📅 Просмотр назначен / 🏁 Сдана / ✖️ Отказ». Первый нажавший агент закрепляется за лидом; карточка обновляется
  у всех агентов. Куда слать — настройка `lead_target`: каждому агенту в личку или в группу агентства.

### Агенты в боте
Агент подключается командой `/agent <AGENT_CODE>` в личке бота. Дальше вся работа идёт в **панели агента** (Telegram
Mini App, см. «Панель агента в Telegram» ниже): кнопка «Панель» слева от поля ввода, кнопка «📋 Панель агента» после
регистрации и «📋 Открыть в панели» на каждой карточке лида. В чат по-прежнему приходят новые лиды с кнопками статуса
и объявления на проверку с кнопками «Опубликовать / Отклонить».

Старые команды работают (обратная совместимость), но в подсказках бота больше не упоминаются — то же самое есть в панели:

| Команда | Что | Где теперь в панели |

### Проверка «точно собственник» (ingest.py → `agent_signals`)
Объявление выкидывается, если:
1. один телефон (из текста описания) в 3+ объявлениях;
2. один аккаунт подал 3+ объявления;
3. одинаковый текст у разных объявлений;
4. **те же фото у другого автора на том же сайте** (перепост) — отпечаток фото dHash, порог ≤4 бит из 64
   (на реальных данных: одно фото = 0–2, разные = 8+). Отсеиваются обе стороны — оригинал от копии не отличить;
5. ИИ по тексту видит агента («наше агентство», комиссия и т.п.);
6. только Facebook (`facebook_signals`): имя/ссылка автора похожи на агентство (realtor, agency, estate, недвижимость,
   უძრავი ქონება, apartments, home…) или пост от страницы; **один автор выложил 2+ разных квартиры** (разные фото и
   параметры); те же фото у другого автора в другой группе. Анонимные посты («Anonymous participant», псевдонимы
   вида ArticulateBee7804) не связать с человеком: для них работают только телефон, текст и фото.
   На пробной выгрузке 30 FB-объявлений → 16 помечены агентами.

Последняя сборка: собрано ss 120 / myhome 96 / канал 100 → 22 отсеяны как агенты, 26 склеены как дубли, **267 в базе**.
Ограничение: агент с одним объявлением, своими фото и обычным текстом пройдёт. Сильнее было бы по реальным телефонам
(отдельный запрос к сайту, на myhome — только с логином).

### Дедуп
Одна квартира на разных сайтах склеивается, если совпали этаж + спальни + площадь (±3 м²) + цена (±10%) **или хотя бы
одно фото**. Только между разными источниками (внутри одного сайта такие совпадения — обычно разные дешёвые квартиры).
Агенту приходят все ссылки. Наблюдение: часть объектов агентства висит на myhome как «от собственника».

### Индексация (Codex)
Для каждого объявления Codex смотрит 2 фото (640px) и текст, возвращает профиль: район, спальни, животные, ремонт,
стиль, свет, мебель, особенности, впечатление 1–5, «как выглядит», чистое описание на русском (без телефонов/ссылок/
сайтов), флаг «похоже на агента» и **факты для карточки** (см. ниже). Кэш: `raw/index_cache.json` (повторная сборка
не тратит Codex). У записей кэша версия `"v": 2`; старые записи (без фактов) при следующем `ingest.py` получают только
факты отдельным коротким вызовом **без фото** (8 объявлений на вызов), профиль и описание остаются как были.
Так сервер сам дополнит свою базу на ближайшем `refresh.sh`, ничего запускать руками не нужно.

### Карточка в формате канала (`facts.py`, поле `details`)
Клиентская карточка выглядит как пост канала @rent_tbilisi_ge, только без хэштегов: строки с эмодзи, и только те,
для которых есть данные. Пример (агентство, реальный пост):
```
🚇 Сололаки · Площадь Свободы
📍 ул. Ивана Мачабели, 9

⭐️ Двухспальная квартира с ретро-гостиной и пианино, 5 минут пешком до площади Свободы

❗️ Эксклюзив

🏢 Квартира · 2 спальни
✨ Исторический дом · смешанный стиль
🏠 68 м² · 3/3 этаж · электрическое отопление · душ

✅ Балкон ✅ Терраса ✅ Двор
✅ Wi-Fi ✅ ТВ ✅ Плита
✅ Духовка ✅ Кондиционер

✖️ Лифт ✖️ Парковка

👬 Жильцов: 1–3
🐕 Животные: можно
🕐 Срок: 6 / 12 мес.

💰 $1000/мес + депозит $1000
0% комиссии

🧭 ~0.6 км от площади Свободы      ← расстояние до места из запроса (если искали рядом с местом)
💡 почему подходит                  ← от подбора
```
Правила: адрес (улица + дом) и точный пин клиенту показываем, как канал (решение Станислава); телефоны, @ники, ссылки,
названия сайтов и агентств вырезаются `core.public()` из каждой строки. Нет «⭐️»-строки → вместо неё описание из индексации.
«✖️» только для важного, чего точно нет: лифт, парковка, кондиционер, духовка, посудомойка, стиральная машина.
Комиссия показывается только у объектов агентства (у чужих объявлений их комиссия не равна условиям агентства).
Английская карточка — те же строки по-английски (`*_en`, словари в `facts.py`), без кириллицы. Карточка агента
(лид, проверка) = та же карточка + адрес как в источнике, точность пина, видео/3D, источник и все ссылки; в админке и
панели та же карточка в списке объявлений («Карточка»), на проверке и в заявке.

Откуда факты (`listing.details`, поля — `docs/schema.md`); детерминированный разбор всегда важнее модели:
| Источник | Разбирается кодом | Остальное |
|---|---|---|

### Видео
- **Telegram (Telethon, `fetch_channel.py`)**: у поста не больше одного видео. Telegram хранит у видео канала несколько
  качеств (оригинал 50–400 МБ и пережатые 480p/720p); берётся самое большое mp4 не больше `VIDEO_MAX_MB` (20 МБ)
  → `raw/video/tg_<id>.mp4` (+ `.json` с шириной/высотой/длительностью). Нет подходящего качества → без видео.
- **t.me/s (`fetch_channel_web.py`, сервер)**: страница отдаёт mp4 только маленьких видео (`<video src>`), их качаем
  с тем же лимитом. У агентства все видео «Media is too big» (оригиналы 10–300 МБ) → сервер их **не качает**, а шлёт
  по `file_id` самого канала (ниже). Файл с тем же именем в `raw/video/` (seed, Telethon) по-прежнему используется.
- **Видео канала агентства без скачивания (`bot.py`)**: бот — админ канала `AGENCY_CHANNEL` (`rent_tbilisi_ge`) и
  отправляет клиенту оригинальное видео поста по `file_id` (без загрузки и без лимита 50 МБ). `file_id` берётся двумя путями,
  оба пишут в таблицу `channel_videos` (`docs/schema.md`):
  - **новые посты**: апдейты `channel_post` / `edited_channel_post` (бот слушает их явно, `ALLOWED_UPDATES`). Каждое
    сообщение канала запоминается с `media_group_id`; сообщения альбома приходят отдельными апдейтами, видео альбома
    находится для объявления `tg<id>` по любому сообщению того же альбома (порядок прихода не важен);
  - **старые посты (backfill)**: `fetch_channel_web.py` читает на t.me/s id сообщения с видео внутри альбома
    (`video_msg`, ссылка `t.me/<канал>/<id>` у плеера, любого размера) → `ingest.py` → `details.video_msg`. Бот при старте
    и каждые 10 минут для объявлений агентства с `video_msg`, но без `file_id`, делает `forwardMessage` из канала в чат
    `VIDEO_STORE_CHAT_ID` (без звука), берёт `message.video.file_id` и сразу удаляет пересланное. ~1 пересылка в секунду,
    уже сделанные не повторяются; удалённый пост помечается и больше не пробуется; ошибка доступа (бот не админ, чат
    недоступен, лимит) — одна строка в логе, проход останавливается до следующего тика. Сверено с Telethon 22.10.2026:
    98 из 100 последних постов агентства с видео, id видео с t.me/s совпали во всех 98.
  - В альбоме видео канала по `file_id` важнее локального файла; если Telegram его не принял, альбом уходит без видео.
- **Как подключить**: в канале @rent_tbilisi_ge → Администраторы → добавить @HomesInGeorgiaBot. Права можно снять все
  (публикация, редактирование, удаление, приглашения): боту нужно только быть админом — так он получает `channel_post`
  и может пересылать сообщения канала. На сервере: `VIDEO_STORE_CHAT_ID` — куда пересылать на секунду (id личного чата
  владельца/агента с ботом или служебной группы, где бот может писать и удалять свои сообщения); не задан → первый чат
  агента / группа агентства из настроек лидов; нет ни одного → backfill пропускается (в логе одна строка).
  `AGENCY_CHANNEL` — другой канал агентства (по умолчанию `rent_tbilisi_ge`).
- **Facebook (Apify)**: подписанная ссылка на mp4 из ответа актора (тип Video/Reel), качается сразу (ссылки протухают)
  → `raw/video/fb<post>.mp4`, тот же лимит. Часто актор отдаёт только превью — тогда без видео.
- **ss.ge / myhome.ge**: ссылки `videoLink` / `youtube_link` / `3d_url` хранятся как URL. mp4-файл с сайта качается как
  видео в альбом. Остальные видеоссылки (HLS `static.ss.ge/…m3u8`, YouTube) качает **`fetch_videos.py` (yt-dlp)** —
  шаг `refresh.sh` после `ingest.py`, только для объявлений без локального видео: ≤720p, ≤ `VIDEO_MAX_MB` (20 МБ;
  сначала форматы с известным размером под лимит, файл больше лимита выбрасывается), одно видео на объявление,
  h264 mp4 (`ffmpeg` в образе: HLS → mp4, YouTube 720p = видео+звук), `raw/video/<id>.mp4` + `.json` (ш/в/длительность).
  Не вышло (YouTube «Sign in to confirm you’re not a bot» — **IP сервера в датацентре YouTube часто блокирует**, гео,
  размер) → ссылка в `raw/video/failed.json`, повтор через `VIDEO_RETRY_DAYS` (3) дня; за проход не больше
  `VIDEO_MAX_PER_RUN` (30) скачиваний. Проверено 22.10.2026 на всех 7 ссылках ss.ge (6 HLS + 1 YouTube): 7/7, 0.1–16.9 МБ
  (вместе ~54 МБ), 2–10 с на ролик. Под карточкой клиента кнопки «🎥 Видео» / «🧊 3D-тур» — только если ссылка https,
  её домен не выдаёт источник (ss.ge, myhome, tnet.ge, facebook, t.me, instagram…; YouTube и Matterport можно) и
  видео **не** скачано (скачанное уже в альбоме).
- **В боте**: альбом = до 4 фото + 1 видео (`core.album`, Telegram разрешает до 10), без подписей; кнопки на текстовой
  карточке после альбома. Локальное видео загружается в Telegram один раз, дальше по `file_id` (таблица `tg_files`).
  Если Telegram не принял видео, альбом уходит без него.

### Подбор (core.py → `search`, только `published`)
1. Место: точка с карты (Mini App), «Где я сейчас» или место текстом («рядом с метро Руставели») — Codex извлекает
   место, Nominatim (OSM) геокодирует. Кандидаты сортируются по расстоянию, радиус по умолчанию 2 км.
2. Один вызов Codex: сообщения клиента + его фото + каталог (одна строка на квартиру) → до 5 лучших с пояснением,
   сколько всего подходит. Бюджет можно превысить максимум на 10% (проверяется ещё и кодом).
3. «❤️ Нравится» → лид в базе и агентам (клиент, запрос, адрес, цена, источник, все ссылки, кнопки статуса). «👎 Не то» учитывается во вкусе.
   «Ещё варианты» — следующие 5 без повторов.

Фото необязательны. Картинки, отправленные файлом (png/heic), приводятся к jpeg.

Коммерческие помещения (`details.property = commercial`: офисы, магазины, торговые площади агентства) в подбор не
попадают, пока клиент сам не попросит словами (`core.COMMERCIAL`: офис, коммерческое помещение, под кафе/магазин, склад,
office, commercial, retail, ოფისი, კომერციული…). Одинаково в режимах `llm` и `hybrid`.

### Гибридный поиск (`search_mode = hybrid`, по умолчанию выключен)
Сейчас каждый подбор отправляет в Codex весь каталог (~410 строк, ~35k токенов, 20–70 с). Гибридный режим:
1. **Один короткий вызов Codex** (расширенный вызов «места», кэш на набор сообщений, как раньше): место для карты +
   бюджет, спальни (от/до), районы (по-русски, как в базе), животные, стиль по-английски, «как понял запрос».
2. **Фильтры в коде**: цена ≤ бюджет × 1.1, спальни, районы, «нет животных» исключается только если у клиента
   животное, радиус × 1.5 от точки, показанные не повторяются. Неизвестные цена/спальни проходят, но идут в конец.
   Если подходит меньше 5 — ослабляем по очереди: районы → спальни → радиус; бюджет никогда.
3. **Ранжирование локальными векторами** (`embed.py`, модель google/siglip-base-patch16-256-multilingual: фото и
   текст ru/en в одном пространстве): фото клиента ↔ фото квартиры (лучшая пара), стиль ↔ фото, стиль ↔ профиль,
   ближе к ❤️ и дальше от 👎, впечатление, расстояние. Веса — `core.W`. Берём топ-20.
4. **Финал**: Codex получает только эти 20 строк (тот же промпт) и выбирает 5 с причинами; если выбрал меньше —
   добиваем следующими по баллу, прошедшими все условия. `final_llm = off`: топ-5 по баллу без второго вызова,
   причина собирается из профиля. Фильтр утечек `public()`, перевод на английский, «ещё» — как в обычном режиме.

Включить / выключить (бот подхватывает без перезапуска, настройка читается на каждый поиск):
```bash
.venv/bin/python embed.py                     # один раз: векторы базы, ~2.5 мин; дальше refresh.sh делает это сам
.venv/bin/python db.py set search_mode hybrid # назад: set search_mode llm
.venv/bin/python db.py set final_llm off      # по желанию: без второго вызова Codex
```
Векторы: `data/vectors.npz` (~7 МБ на 468 объявлений, float32), инкрементально: отпечаток = модель + фото + профиль,
пропавшие выпадают. Без файла векторов hybrid работает только на фильтрах + впечатлении/расстоянии.
Зависимости: `torch transformers sentencepiece protobuf` (`requirements-embed.txt`; в .venv +~0.9 ГБ),
модель 1.5 ГБ в кэше Hugging Face (`~/.cache/huggingface`), в памяти бота ~1.5 ГБ, первая загрузка ~5 с,
кодирование фото клиента ~0.1 с (MPS на M4). Эмбеддинг базы ~0.1 с на фото.
Оценка (13 запросов, 3 режима, листы с фото): [eval-search.md](eval-search.md) — 0 нарушений во всех режимах,
hybrid ≈24 с против ≈40 с, промпт в 12 раз меньше; без финального Codex ≈8 с.

### Карта
`webapp/index.html` — Leaflet + OSM, поиск места, перетаскиваемая точка, радиус 1/2/3/5 км, отправляет точку боту через
`Telegram.WebApp.sendData`. Задеплоено на Vercel (проект `tbilisi-rent-map`, команда giganiga666's projects) без GitHub —
через Vercel MCP `create_deployment` с одним файлом. Боту публичный адрес не нужен: он сам опрашивает Telegram.

**Где квартира на карте.** Та же страница (`admin.py` отдаёт её на `/map`) с параметрами
`?pin=lat,lng&prec=<geo_precision>&title=Ваке · $800&lang=ru` работает в режиме просмотра. Она ставит пин и ничего
не отправляет боту. Внизу подпись и кнопка «Закрыть» (`Telegram.WebApp.close`; если страницу открыли из панели, кнопка
называется «Назад»). Подпись зависит от `geo_precision`: `точный` → «Расположение квартиры», `примерный` →
«Примерное расположение: улица», `район` → «Примерное расположение: район». Точку не прячем: так решил Станислав,
канал агентства тоже даёт ссылку на карту.
- Клиент: кнопка «📍 На карте» (`core.card_keyboard`, web_app, клиенты всегда в личке) стоит под текстовой карточкой
  рядом с ❤️/👎: на альбом кнопки не вешаются. После лайка она остаётся. В заголовке только район и цена, id
  объявления (по нему видно источник) не передаётся.
- Агент: в карточке лида есть строка «📍 Точка: <точность>» и кнопка «📍 На карте» (`core.lead_keyboard`). В личке это
  web_app-кнопка, в группе обычная URL-кнопка на ту же страницу: web_app-кнопки в группах Telegram не разрешает.
  В карточке проверки показана точность. В админке и панели ссылка «📍 На карте» есть в списке объявлений, на проверке
  и в заявке, а в заявке ещё и мини-карта Leaflet с пином.
- Без координат или без `AGENT_APP_URL` кнопок нет.

Скриншоты: `proof/map_zone/` (пересъёмка: `proof/map_zone/shoot.py`).

### Автообновление
`refresh.sh` — один проход: источники из базы → сборщики → `ingest.py` → `fetch_videos.py` (видеоссылки → mp4) → `db.py sync`. Упавший сборщик оставляет
прошлые данные, упавший ingest — прошлую базу; два запуска одновременно не идут (замок `data/refresh.lock`).
Переменные: `PY` (python, по умолчанию `.venv/bin/python`), `TG` (tg-runtime для каналов), `SKIP_FACEBOOK=1`
(Apify платный). Расписание пока **не установлено**. Варианты:
```bash
# cron (crontab -e), каждые 6 часов:
0 */6 * * * /Users/stnslv/Dev/Projects/rent-tbilisi-ai/refresh.sh >> /Users/stnslv/Dev/Projects/rent-tbilisi-ai/data/refresh.log 2>&1
```
или launchd: `~/Library/LaunchAgents/ge.rentintbilisi.refresh.plist` с `ProgramArguments` = путь к `refresh.sh`,
`StartInterval` = 21600, `StandardOutPath` = `data/refresh.log`, затем `launchctl load <plist>`.
Бот подхватывает новую базу без перезапуска (читает SQLite на каждый подбор).

### Админка (`admin.py`)
Веб-админка для агентства поверх той же базы и тех же функций `core.py`, что и бот (решения и статусы общие).
Стек: только стандартная библиотека Python (`http.server`) + Pillow для превью фото, HTML рендерится на сервере, без JS-сборки.

```bash
echo 'ADMIN_PASSWORD=придумайте-длинный-пароль' >> .env
.venv/bin/python admin.py            # http://127.0.0.1:8080
```

| Страница | Что |
|---|---|
| Объявления | таблица с фильтрами (статус, источник, район, цена от/до), превью фото, ссылка на источник, по 50 на страницу |

| Статистика | за период: запросы (поиски), клиенты, лайки, заявки, просмотры, сдано, отказы; заявки по источникам и агентам |

| `ADMIN_TG_IDS` | — | Telegram id через запятую: пускать в панель, даже если человек не агент (владелец агентства) |
| `TG_AUTH_MAX_AGE` | `86400` | сколько секунд `initData` считается свежим |
| `ADMIN_HOST` / `ADMIN_PORT` | `127.0.0.1` / `8080` | на сервере оставить `127.0.0.1` и поставить перед админкой HTTPS-прокси (Caddy/Nginx/Dokploy) |
| `ADMIN_SECURE_COOKIE` | — | `1` — всегда ставить cookie `Secure` (за HTTPS-прокси без `X-Forwarded-Proto`; с ним — автоматически) |
| `APP_DB` | `data/app.db` | база |
| `PHOTO_DIR` | `raw/img` | единственная папка, из которой отдаются фото (по id объявления и номеру, без путей из запроса) |
| `ADMIN_LOG` | — | `1` — писать каждый запрос в лог |

Безопасность: cookie с подписью HMAC (HttpOnly; вход по паролю — SameSite=Strict, 7 дней; панель в Telegram — 12 ч),
POST с чужого Origin отклоняется, неверный пароль — задержка 1 с. Ссылки на источники видны только в админке и панели
(они для сотрудников). Вёрстка: на узком экране (≤760 px) таблицы превращаются в карточки, на широком длинные ссылки
переносятся, кнопки действий компактные — ничего не вылезает за правый край, шапка той же ширины, что и контент.

### Панель агента в Telegram (Mini App)
Та же `admin.py`, открытая внутри Telegram как Web App. Раскладка под телефон (~390 px): вкладки снизу
(Заявки · Проверка · Объявления · Источники · Ещё → Агенты, Настройки, Статистика), карточки вместо таблиц, крупные кнопки,
нативная кнопка «Назад» Telegram на странице заявки. Цвета бренда поверх темы Telegram.

- **Заявки**: по умолчанию «Мои и новые» (закреплённые за агентом + ещё никем не взятые), фильтры «Все» и по статусу.
  Карточка заявки: фото объекта, статус четырьмя кнопками (как в Telegram: В работе / Просмотр назначен / Сдана / Отказ;
  агент закрепляется за заявкой при первой смене), клиент и его запрос, «Написать в Telegram» (и «Позвонить», если есть
  телефон), ссылки на объявление-источник, исходный текст, история.
- **Проверка, Объявления, Источники, Агенты, Настройки, Статистика** — то же, что в админке.
- Решения из панели и из админки сразу правят уже отправленные карточки в Telegram (лид: новый статус и агент;
  проверка: «✅ Опубликовано · @агент», кнопки убираются) — через Bot API с тем же `BOT_TOKEN`.

**Вход.** `/tg` загружает `telegram-web-app.js`, берёт `Telegram.WebApp.initData` и отправляет на `/tg/auth`. Сервер
проверяет подпись по документации Telegram (secret = HMAC_SHA256("WebAppData", BOT_TOKEN), HMAC_SHA256 от
отсортированных строк `key=value` без `hash`), свежесть `auth_date` (по умолчанию 24 ч, `TG_AUTH_MAX_AGE`) и пускает
только **активного агента** из базы (агент, добавленный в админке по @username, привязывается здесь же) или id из
`ADMIN_TG_IDS`. Сессия — подписанная cookie на 12 ч; отключённый в админке агент теряет доступ сразу. В браузере на
компьютере вход по паролю остаётся как был (`/login`).

**Кнопки в боте.** Если задан `AGENT_APP_URL`, бот:
- ставит агентам **кнопку меню чата** «Панель» (`setChatMenuButton` с `chat_id`, тип `web_app`) — при регистрации
  `/agent`, при любом сообщении агента и при старте бота для всех известных агентов; клиентам кнопку не ставит, отключённому
  агенту возвращает обычную. BotFather для этого **не нужен**;
- после `/agent <код>` присылает кнопку «📋 Панель агента». Это inline-кнопка `web_app`, а не кнопка клавиатуры: Mini App,
  открытый с reply-клавиатуры, не получает `initData` с пользователем, и сервер не смог бы проверить вход;
- добавляет к карточке лида в личке «📋 Открыть в панели» (`<AGENT_APP_URL>/tg?lead=<id>` → сразу эта заявка).
  В группе агентства такой кнопки нет: Telegram разрешает `web_app`-кнопки только в личных чатах.
Без `AGENT_APP_URL` бот работает как раньше и ничего из этого не делает.

**Запуск через Cloudflare quick tunnel** (Telegram открывает Mini App только по HTTPS):
```bash
.venv/bin/python admin.py                              # слушает только 127.0.0.1:8080
cloudflared tunnel --url http://127.0.0.1:8080         # печатает https://<случайное-имя>.trycloudflare.com
# в .env: AGENT_APP_URL=https://<случайное-имя>.trycloudflare.com, затем перезапустить бота и админку
```
Адрес quick tunnel меняется при каждом запуске `cloudflared` — после смены обновить `AGENT_APP_URL` и перезапустить бота
(он заново поставит кнопки меню). Для постоянной работы — именованный туннель Cloudflare или свой домен за Caddy/Nginx.
За туннелем админка понимает `X-Forwarded-Proto` (cookie получают `Secure`; у сессии Mini App `SameSite=None`, потому что
Telegram Web показывает Mini App во фрейме) и `X-Forwarded-Host` (проверка Origin у POST принимает адрес туннеля).
Встраивать страницы во фрейм разрешено только `web.telegram.org` (`Content-Security-Policy: frame-ancestors`).

Проверить без Telegram: `.venv/bin/python test/e2e/run.py --fake-llm` (сценарий 17 открывает панель в Chrome с
подписанным тестовым токеном `initData`), скриншоты — `proof/miniapp/`.

## Сервер (Dokploy)
Один контейнер из `Dockerfile` (python:3.12-slim, пользователь `app`, без playwright и codex): `start.sh` при старте
распаковывает seed в пустые тома, делает `db.py init` (+ `db.py sync --partial`, если база пустая, а `listings.json` есть),
запускает `admin.py` на `0.0.0.0:8080`, цикл `refresh.sh` раз в `REFRESH_HOURS` и `bot.py`. Если любой процесс упал,
контейнер выходит через 5 с (Dokploy/Docker перезапускает); всё пишется в stdout (логи в Dokploy). Health check —
`GET /login` админки = 200. Образ ~100 МБ.

**Деплой (Application → Provider «Drop», Build Type «Dockerfile», путь `Dockerfile`):**
```bash
./seed.sh                                   # необязательно: текущая база → /tmp/seed.tgz (~340 МБ, см. ниже)
scripts/make_drop_zip.sh                    # → /tmp/homes-drop.zip (~250 КБ, код по .dockerignore)
SEED=1 scripts/make_drop_zip.sh             # то же + seed/seed.tgz внутри (~340 МБ)
# локальная проверка: docker build --platform linux/amd64 -t homes-ai . && docker run -p 8080:8080 -e ... homes-ai
```
Тома (Advanced → Mounts → Volume): `homes-data` → `/app/data` (SQLite, `listings.json`, фото клиентов, `vectors.npz`),
`homes-raw` → `/app/raw` (сырые посты, `raw/img`, кэши индексации и геокодинга). Порт: домен Dokploy на порт **8080**
с HTTPS → этот адрес в `AGENT_APP_URL`. Боту входящие порты не нужны (long polling).

**Seed.** Без него первый старт сам строит базу (`TG_FETCH=web`, `LLM_PROVIDER=openai`): все источники + индексация
каждого объявления моделью — это деньги и ~30–60 мин. `seed.sh` пакует `listings.json`, `raw/index_cache.json`,
`raw/geo_cache.json`, `raw/dropped_agents.json`, сырые файлы источников и все фото, на которые они ссылаются (+ копии 640px;
фото больше 1280px ужимаются), абсолютные пути Mac → `raw/img/...`. Тогда следующие обновления индексируют только новые
объявления (кэш). `start.sh` распаковывает `/app/seed/seed.tgz` (или путь из `SEED`), только если в томах нет
`data/listings.json` и `raw/img` пуст. Если zip с seed слишком большой для загрузки: залить `seed.tgz` в том на сервере
(`/var/lib/docker/volumes/<том data>/_data/seed.tgz`), поставить `SEED=/app/data/seed.tgz` и перезапустить; чтобы
до этого контейнер не начал строить базу сам — `REFRESH_ON_START=0`.

| Переменная | Значение на сервере | Что |
|---|---|---|
| `BOT_TOKEN` | токен @BotFather | бот и проверка входа в панель агента |
| `AGENT_CODE` | секрет | `/agent <код>` в боте |
| `ADMIN_PASSWORD` | длинный пароль | вход в админку из браузера |
| `AGENT_APP_URL` | `https://<домен Dokploy>` | кнопки панели агента в боте |

| `LLM_PROVIDER` | `openai` (в образе по умолчанию) | `codex` — только на Mac с Codex CLI |
| `OPENAI_BASE_URL` | `https://api.proxyapi.ru/openai/v1` | любой OpenAI-совместимый Chat Completions |
| `OPENAI_API_KEY` | ключ ProxyAPI | |

| `VIDEO_MAX_MB` | `20` | лимит локальных видео (Telegram-сборщики, yt-dlp) |
| `VIDEO_RETRY_DAYS`, `VIDEO_MAX_PER_RUN` | `3`, `30` | yt-dlp: повтор неудачной ссылки через N дней; скачиваний за проход |

Гибридный поиск (`search_mode=hybrid`, `embed.py`) в образ по умолчанию **не входит**: torch + transformers весят ~1 ГБ.
Собрать с ними: `--build-arg WITH_EMBED=1` (CPU-колёса torch, `requirements-embed.txt`); модель SigLIP скачается при первом
запуске. Без них `embed.py` в `refresh.sh` пишет ошибку и пропускается, подбор в режиме `llm` работает.

## Модель
Codex CLI по подписке (`llm.py` → `codex exec --output-schema`, картинки через `-i`), без API-ключей — так решил Станислав.
Один вызов 10–60 с. На первой сборке упёрлись в лимит подписки (сброс через ~20 мин) → фото для модели уменьшены до 640px.
На сервере `LLM_PROVIDER=openai`: OpenAI-совместимый Chat Completions через httpx (structured output `json_schema` strict,
фото base64 640px, повторы с паузой на 429/5xx и обрывы), см. «Сервер (Dokploy)».

## Известные проблемы / дальше
- Админка в браузере: пользователь один (общий пароль). Агенты входят в панель через Telegram, каждый под собой.
- Панель агента: quick tunnel Cloudflare меняет адрес при каждом запуске; в Telegram Web/Desktop браузеры с жёсткой
  блокировкой сторонних cookie могут не сохранить сессию во фрейме (на телефонах Mini App открывается без фрейма).
- **Водяные знаки на фото**: myhome.ge (по центру) и ss.ge (в углу) — клиент может понять источник. Не исправлено.
- Бот живёт на Mac: при закрытой крышке/сне не работает; один раз обёртка `run_bot.sh` пропала ночью без видимой причины.
  Для 24/7 нужен свой сервер (Dokploy) + файл авторизации Codex, или перевод модели на API.
- Автообновление (`refresh.sh`) готово, но расписание не поставлено. Сборщики берут только последние N объявлений,
  поэтому старое, но ещё живое объявление, выпавшее из окна, тоже станет `gone`.
- `fetch_channel.py` и `fetch_facebook.py` пока читают `sources.json`, а не базу напрямую (его пишет `db.py export-sources`).
- Facebook: в постах свободный текст на трёх языках — цена/площадь/этаж/адрес достаются регулярками, часто пусто
  (адрес чаще всего только район). Цена в лари переводится по курсу 2.7. Группы ищутся вручную (поиск групп через Apify
  у `easyapi~facebook-groups-search-scraper` вернул 0, AI-поиск у `thedoor` — только на платном плане).
- Точка с карты и картинка-файлом не протестированы end-to-end (инструмент рабочего аккаунта не умеет их слать).
