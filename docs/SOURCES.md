# Дополнительные источники объявлений: Livo, Korter, Facebook, Instagram

Пункты 3 и 4 плана (DEVELOPMENT_PLAN.md). Проверено 3 ноября 2026 года на живых сайтах.

Как устроен сбор сейчас: `bot/refresh.sh` по расписанию запускает сборщики `bot/fetch_*.py`. Каждый пишет
`bot/raw/<источник>.json`, затем `bot/ingest.py` приводит всё к одному виду, склеивает дубли (по фото и параметрам),
отмечает агентов, и `db.py sync` кладёт объявления в Postgres. Оттуда они попадают в ленту «Новые объявления»
воронки 1 и в поиск бота. Новый источник = один сборщик + одна функция преобразования в `ingest.py`.

## Итог

| Источник | Способ | Статус | Деньги |
|---|---|---|---|
| **Livo** (livo.ge) | данные из HTML страницы поиска, обычный HTTP | ✅ подключён: `fetch_livo.py` | бесплатно |
| **Korter** (korter.ge) | данные из HTML (`window.INITIAL_STATE`), фильтр «собственник» | ✅ подключён: `fetch_korter.py` | бесплатно |
| **Instagram** | официальный Graph API: поиск по хэштегам и Business Discovery | исследовано, нужен доступ Meta | бесплатно, но нужна проверка приложения в Meta |
| **Facebook-группы** | официального API нет с апреля 2024 | работает через Apify (`fetch_facebook.py`, было до нас) | ~$4 в месяц |

## Livo — подключён

- Livo принадлежит TNET, той же компании, что и myhome.ge. База объявлений общая: одинаковые ID (26,2–26,4 млн),
  одни и те же поля (`bedroom`, `price` в трёх валютах, `user_type`), фото с `static-api-statements.tnet.ge`.
- Фильтры в URL такие же, как у myhome: `deal_types=2` (аренда), `real_estate_types=1` (квартиры), `cities=1`
  (Тбилиси), `owner_type=physical` (собственники). На 3 ноября: **3 627** объявлений, по 24 на страницу.
- Главное отличие от myhome: myhome закрыт Cloudflare, и его сборщику нужен обход защиты. Livo отдаёт те же данные
  обычным запросом. Livo заменяет myhome там, где myhome не открывается, а одинаковые квартиры с двух сайтов склеивает
  dedupe.
- Разбор: результаты лежат в потоке данных Next.js (`self.__next_f`), сборщик вынимает из него объекты объявлений.
  Преобразование переиспользует `from_myhome`: ID `lv…`, источник `livo.ge`.
- Прогон 03.11: 96 объявлений, у всех цена, площадь, этаж и фото; описание у 81 из 96.
- Ограничение: нет точного пина (координаты в выдаче пустые), адрес геокодируется как у myhome.

## Korter — подключён

- Страницы рендерятся на сервере, состояние приложения лежит в `window.INITIAL_STATE`. API-ключ и вход не нужны.
- Список: `/en/apartments-for-rent-tbilisi?seller_type=owner&page=N`, по 20 на страницу. На 3 ноября: **1 493**
  объявления от собственников (всего в аренде 18 982, остальное риелторы). В списке есть цена, площадь, комнаты,
  этаж, этажность, район и **пин дома**.
- Страница объявления добавляет описание, все фото, спальни, санузлы, балкон/террасу, видео и тип продавца. Кэш
  по ID в `raw/korter_details.json`: при обновлении открываются только новые объявления.
- Прогон 03.11: 80 объявлений, у всех 80 цена, фото, спальни и пин, у всех тип продавца «owner»; описание у 69 из 80.
- Телефоны со страницы не сохраняются (как у ss.ge и myhome).
- Объявления в лари переводятся в доллары по курсу ingest (2.7).

## Instagram — исследовано

Бесплатный и законный путь есть, но только через официальный Graph API, и он требует подготовки со стороны агентства:

1. **Поиск по хэштегам** (`ig_hashtag_search` → `recent_media`). Отдаёт публичные посты по хэштегу, например
   `#ქირავდება`, `#аренда_тбилиси`, `#tbilisirent`. Ограничения Meta: 30 разных хэштегов за скользящие 7 дней на
   один аккаунт, `recent_media` только за последние 24 часа. Для обновления раз в 6 часов этого хватает.
2. **Business Discovery.** Публичные посты конкретных бизнес- и авторских аккаунтов по username, например
   агентств-конкурентов. Личные аккаунты так не читаются.

Что нужно от агентства:
- Instagram-аккаунт агентства, переведённый в Business или Creator и привязанный к странице Facebook.
- Приложение в Meta for Developers и проверка Meta (App Review) на доступ Instagram Public Content Access и
  `instagram_basic`. Проверка идёт от нескольких дней до нескольких недель, и её исход не гарантирован.
- Долгоживущий токен в `.env`.

После этого сборщик пишется по той же схеме, что и остальные: `fetch_instagram.py` → `raw/instagram.json` →
`from_instagram`. Подписи разбираются тем же способом, что посты из Facebook и Telegram: регулярные выражения плюс
нейронка. Делать сборщик без токена смысла нет: его нечем проверить.

## Facebook — исследовано

- **Официального пути нет.** Meta убрала Groups API для сторонних приложений в Graph API v19 (январь 2024),
  интеграции с группами отключены с 22 апреля 2024. Marketplace API не было никогда. Через Graph API можно читать
  только страницы, которыми управляешь сам.
- **Сейчас работает Apify** (`bot/fetch_facebook.py`, был в боте до нас): готовый сборщик публичных групп, около
  $0.26 за прогон. Он запускается раз в 48 часов (`FB_EVERY_HOURS`), выходит около $4 в месяц. Отключается флагом
  `SKIP_FACEBOOK=1`. Это самый дешёвый рабочий вариант на сегодня.
- **Собственный сборщик в браузере (Camoufox и подобные).** Технически возможен, но требует аккаунта Facebook,
  который будет залогинен в автоматическом браузере, и маскировки под человека. Это нарушает правила Facebook:
  аккаунт будут банить, сборщик придётся постоянно чинить. У самого Camoufox был годовой перерыв в поддержке, и его
  маскировка устарела. Мы его не делали и не рекомендуем: $4 в месяц за Apify дешевле, чем поддержка своего.
- Если Facebook важен, разумный порядок: оставить Apify и следить, сколько объявлений из групп реально доходит до
  сделок. Решение о своём сборщике принимать по этим цифрам.

## Что изменено в коде

- `bot/fetch_livo.py`, `bot/fetch_korter.py` — новые сборщики.
- `bot/ingest.py` — `from_livo`, `from_korter`, загрузка `raw/livo.json`, `raw/korter.json`, `raw/korter_details.json`.
- `bot/refresh.sh` — оба сборщика в цикле обновления. Отключаются флагами `SKIP_LIVO=1`, `SKIP_KORTER=1`.
- `backend/app/services/properties.py`, `backend/app/telegram/notify.py`, `frontend/src/lib/format.ts` — источники
  `livo` и `korter` в CRM и уведомлениях.
- `bot/test/test_sources.py` — тесты разбора страниц и преобразования, без сети.
