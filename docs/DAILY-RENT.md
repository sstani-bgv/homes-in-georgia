# Посуточная аренда (Daily Rent) в CRM

Раздел **«Посуточная аренда»** — бывшее приложение ApartFlow (Ираклий, Node + SQLite, бот `@Daily_Rent_in_Tbilisi_bot`),
перенесённое в CRM целиком. Отдельного сервера и фрейма больше нет: данные в Postgres CRM (таблицы `dr_*`), экран —
обычные страницы CRM.

## Кто видит

| Роль | «Посуточная аренда» | Остальная CRM |
|---|---|---|
| Суперадмин, админ | да | как обычно |
| **Менеджер посуточной аренды** (`daily_rent_manager`) | да | **ничего** |
| Оператор, агент, рекрут | нет | как обычно |

Роль вне лестницы уровней. `api/deps.current_user` пускает её только в `/api/auth/me`, `/api/daily-rent/*` и фото
квартир `/api/media/daily/*` — новый раздел CRM для неё закрыт сам собой.

## Что где

| Экран | Что делает (как в ApartFlow) |
|---|---|
| Сводка | итоги за месяц / 3 мес / год / всё: пришло, чистая прибыль, собственникам, платформе, ночи и загрузка, средняя цена ночи; доход по месяцам; по квартирам; **«К выплате»** собственникам — «Выплатить всё» и по одному проживанию |
| Квартиры | список; карточка: собственник, контакт, счёт для выплат, доля платформы (по умолчанию 20 %, собственнику 80 %), платформы, статус, комнаты, коммунальные счета, заметки |
| Квартира → Проживания | проживания и цифры за период, отчёт собственнику за период (копировать) |
| Квартира → Фото и сайт | фото (до 20, первое — обложка), цена за ночь, район, описание — для показа на hge.ge позже |
| Квартира → Календари площадок | iCal Airbnb / Booking / другой площадки: наша ссылка для площадки и ссылка площадки для нас |
| Проживание (окно) | платформа, даты, гость, сумма и валюта, налог, Booking fee, статус оплаты; расходы (кто оплатил); расклад денег; текст отчёта; «Выплачено владельцу» |
| Шахматка | квартиры × дни месяца: проживания, брони площадок, ручные закрытия; двойная занятость и брони без внесённого проживания; клик — новое проживание, закрыть даты, внести деньги по брони |
| Уборки и персонал | уборки (часы × ставка 16,70 ₾), сотрудники |
| Журнал | каждое изменение: кто, когда, что было → стало (таблица `events`, entity `dr_*`) |

## Деньги (как `calcBk` в ApartFlow)

```
налог      = пришло × налог%                    (Airbnb по умолчанию 1 %, остальные 0)
fee        = Booking fee (только Booking)
расходы    = расходы проживания в его валюте     (другая валюта — по курсу НБГ)
чистая     = пришло − налог − расходы − fee
платформе  = чистая × доля платформы + расходы, оплаченные платформой + fee
собственнику = чистая × (100 − доля) + расходы, оплаченные собственником
```
Округление до копеек на каждом шаге, как в ApartFlow. Итоги в долларах — по курсу НБГ (`site_feed.rates()`).
Доля платформы берётся из квартиры в момент создания проживания; смена доли у квартиры прошлые проживания не меняет.
Удаление «мягкое» (`deleted_at`): проживание удаляется вместе с его расходами, квартиру с проживаниями удалить нельзя.

## Календари Airbnb / Booking (iCal)

- **Наша лента** для площадки: `PUBLIC_URL/api/public/daily-rent/ical/<токен>.ics` — без входа, токен секретный.
  Отдаёт все занятые ночи квартиры, кроме событий самой этой площадки (их брони, проживания с неё, «эхо»).
- **Их лента**: воркер забирает ссылку площадки каждые `DAILY_RENT_ICAL_MINUTES` (15) минут, события становятся
  бронями площадки, пропавшие снимаются. Разрешены только адреса Airbnb, Booking, VRBO, Google, iCloud и
  `DAILY_RENT_ICAL_HOSTS`.
- **Двойная занятость**: о новой бот CRM пишет суперадминам, админам и менеджерам посуточной аренды с кнопкой
  «Открыть шахматку» (`notify.daily_rent_conflicts`). Первый запуск только запоминает старые пересечения.

## Перенос из ApartFlow (один раз)

```bash
# копия базы (только чтение, на сервере ничего не меняется)
ssh root@<prod> 'python3 -c "import sqlite3,sys; c=sqlite3.connect(\"file:/opt/apartflow/data/apartflow.db?mode=ro\",uri=True); [sys.stdout.write(l+\"\n\") for l in c.iterdump()]"' | sqlite3 apartflow.db
docker compose cp apartflow.db api:/tmp/apartflow.db
docker compose exec -w /app/backend api python -m app.importers.apartflow /tmp/apartflow.db            # проверка, всё откатывается
docker compose exec -w /app/backend api python -m app.importers.apartflow /tmp/apartflow.db --commit   # запись, если проверки прошли
```
Проверки: число живых и удалённых записей по каждой таблице; суммы по валютам (пришло, расходы); для каждого
проживания чистая, доля собственника и платформы по формуле ApartFlow (пересчитана отдельно по сырым данным) против
CRM — до копейки. Есть расхождение — ничего не пишется. Повторный запуск безопасен (сверка по `legacy_id`).
На 2026-11-15 на копии: 7 квартир, 69 проживаний (+1 удалённое), 140 расходов, 2 сотрудника, 278 записей журнала,
пришло $24 423,14 + ₾16 615,82, ошибок 0. 22 расхода ссылаются на проживания, которых в ApartFlow не было — они
переносятся без проживания (`extra.legacy_booking_id`), в деньгах не участвуют (как и в ApartFlow).

## Переход (cutover)

1. Деплой CRM с миграцией `0022` (только новые таблицы `dr_*`).
2. Запустить перенос (выше) — сразу перед переходом, чтобы не потерять последние записи.
3. В Airbnb / Booking заменить ссылки на наши ленты новыми из «Календари площадок» (в ApartFlow их не было).
4. Остановить ApartFlow (`systemctl stop apartflow`, убрать из Caddy) и бота `@Daily_Rent_in_Tbilisi_bot`; базу и
   бэкапы оставить как архив. Переменные `DAILY_RENT_URL` / `DAILY_RENT_SSO_SECRET` в `.env` CRM больше не нужны.

## Автопилот (services/daily_rent_auto.py, 2026-11-23)

Чтобы менеджеру не вписывать руками то, что площадки и так знают:

| Что | Как работает |
|---|---|
| **Бронь Airbnb → проживание** | После каждой синхронизации календарей событие Airbnb «Reserved» само становится проживанием: квартира, даты, Airbnb, код брони (HM…) в комментарии, `payment_status = pending`, сумма пустая («без суммы»). Гость перенёс даты — проживание переезжает (пока без денег). Бронь отменена — проживание без денег удаляется, с деньгами остаётся и помечается «отменена на Airbnb». Проживание Airbnb, внесённое руками на те же ночи, не дублируется. Брони, закончившиеся больше 60 дней назад, не трогаются. Лента Booking не создаёт ничего: в ней бронь и закрытые даты одинаково «CLOSED - Not available». |
| **«Сегодня»** | `GET /api/daily-rent/today`, первая вкладка раздела: заезды / выезды сегодня, кто живёт, заезды на неделе, проживания без суммы, уборки сегодня, что можно выплатить, загрузка на 30 дней, «Обратите внимание» (свободно ≥3 ночей подряд в ближайшие 2 недели; скрытая квартира с будущими бронями; отменённая на Airbnb бронь с внесёнными деньгами). |
| **Утренняя сводка** | Воркер, раз в день с 09:00 (Тбилиси): уборки на сегодняшние выезды, затем «Сегодня» в Telegram менеджерам посуточной аренды (`notify.daily_rent_digest`). |
| **Уборки** | На каждый выезд дня — уборка: уборщик = «сотрудник» проживания, ставка 16,70 ₾/ч, в заметке гость и следующий заезд. Часы вносятся после уборки. |
| **Отчёты собственникам** | 1-го числа (или в первый день работы воркера после) — отчёт за прошлый месяц по каждой квартире менеджерам, по сообщению на квартиру, чтобы переслать собственнику (`notify.daily_rent_owner_reports`). В день выкатки только запоминается прошлый месяц — рассылка с ближайшего 1-го. |

Всё пишется в журнал (`events dr_*`, автор «авто»). Следующие шаги: суммы и брони Booking из писем площадок; уведомления уборщикам и собственникам напрямую (нужны их Telegram).

## Отчёты на трёх языках

Отчёт по проживанию и отчёт за период собираются на русском, английском и грузинском (`services/daily_rent.T`):
переводятся подписи, месяцы, «ночи» и формат денег ($1,234.50 в английском, $1 234,50 в русском и грузинском). То, что
ввели руками (имя гостя, адрес, комментарии), остаётся как есть. В карточке отчёта переключатель Русский / English /
ქართული и кнопка «Копировать». У квартиры поле «Язык отчётов» (`dr_apartments.report_lang`, миграция 0038): на нём
отчёт открывается и уходит ежемесячный отчёт 1-го числа.
